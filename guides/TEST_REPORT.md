# Meep Python Test Report

**Date:** 2025-02-20
**Environment:** pymeep 1.31.0 (conda-forge), Python 3.13, NumPy 2.x, WSL2 on Windows

---

## Executive Summary

We ran all 148 unique Python files from `python/examples/` (83 files) and `python/tests/` (65 files) using an automated batch runner under WSL2. Each file was executed twice across two independent batch runs to verify reproducibility.

| Result | Count | Percentage |
|--------|-------|------------|
| PASS   | 76    | 51%        |
| FAIL   | 25    | 17%        |
| TIMEOUT| 47    | 32%        |
| **Total** | **148** | **100%** |

**Key finding:** Of the 25 failures, none are fundamental problems with meep itself. All are caused by missing optional packages (13), deprecated NumPy APIs (2), missing external tools (2), missing data files (2), scripts requiring CLI arguments (3), or outdated example code using stale API names (3). The 47 timeouts are overwhelmingly caused by CPU contention from parallel batch execution, not by actual hangs. Files that timed out in one run frequently passed in the other when given more CPU time.

## Failure Analysis by Root Cause

### 1. Missing `parameterized` Package (10 tests)

**Impact:** 10 test files fail immediately at import.
**Fix:** `pip install parameterized`

These tests use `@parameterized.expand()` for data-driven test cases. The `parameterized` package is not installed by default with conda-forge pymeep.

| File | Error |
|------|-------|
| test_adjoint_cyl.py | `ModuleNotFoundError: No module named 'parameterized'` |
| test_adjoint_utils.py | same |
| test_binary_grating.py | same |
| test_binary_partition_utils.py | same |
| test_chunk_balancer.py | same |
| test_get_epsilon_grid.py | same |
| test_mode_decomposition.py | same |
| test_pml_cyl.py | same |
| test_refl_angular.py | same |
| test_special_kz.py | same |

### 2. NumPy 2.x Compatibility (2 files)

**Impact:** 2 example files fail due to removed NumPy 1.x APIs.
**Fix:** Replace deprecated calls.

| File | Deprecated API | Replacement |
|------|---------------|-------------|
| antenna-radiation.py | `np.trapz(...)` | `np.trapezoid(...)` |
| solve-cw.py | `np.complex_` | `np.complex128` |

These are simple one-line fixes. NumPy 2.0 removed `np.trapz` (renamed to `np.trapezoid`) and `np.complex_` (use `np.complex128`).

### 3. Missing External Tools (2 files)

**Impact:** 2 example files fail because `h5topng` is not installed.
**Fix:** `sudo apt install h5utils`

| File | Error |
|------|-------|
| cherenkov-radiation.py | `FileNotFoundError: No such file or directory: 'h5topng'` |
| wvg-src.py | same |

`h5topng` is part of the `h5utils` package and is used to convert HDF5 field output to PNG images.

### 4. Missing Data Files (2 files)

**Impact:** 2 example files fail because they depend on pre-generated data that is not included in the repository.

| File | Missing File | Notes |
|------|-------------|-------|
| eps_fit_lorentzian.py | `mymaterial.csv` | User must provide their own material data CSV |
| plot_radiation_pattern_dipole.py | `dipole_radiation_pattern.npz` | Must be generated by running a companion simulation first |

### 5. Requires CLI Arguments (3 files)

**Impact:** 3 example files exit with usage errors because they require command-line arguments.
**Not bugs** -- these scripts are designed to be run with arguments.

| File | Required Arguments |
|------|--------------------|
| dipole_in_vacuum_1D.py | `{x,y}` (dipole polarization) |
| dipole_in_vacuum_cyl_off_axis.py | `{x,y} dipole_pos_r` |
| dipole_in_vacuum_cyl_on_axis.py | `{x,z}` (dipole polarization) |

### 6. API / Code Bugs (3 files)

**Impact:** 3 example files fail due to outdated API usage that no longer matches the installed meep version. These need upstream fixes.

| File | Error | Root Cause |
|------|-------|------------|
| cavity_arrayslice.py | `TypeError: Simulation.get_array() got multiple values for argument 'component'` | Positional `Volume` argument conflicts with keyword `component` due to API signature change |
| mpb_line_defect.py | `AttributeError: 'ModeSolver' has no attribute 'fix_efield_phase'` | Method was renamed to `fix_field_phase` |
| waveguide_crossing.py | `TypeError: only 0-dimensional arrays can be converted to Python scalars` | `EigenModeSource` amplitude parameter receives an array instead of a scalar |
| binary_grating_levelset.py | Same amplitude TypeError as waveguide_crossing.py | Same root cause |

### 7. Missing Optional Packages (2 files)

**Impact:** 2 files fail because optional packages are not installed.

| File | Missing Package | Fix |
|------|----------------|-----|
| ring_gds.py | `gdspy` | `pip install gdspy` (GDSII layout library) |
| test_adjoint_jax.py | `jax` | `pip install jax` (automatic differentiation for adjoint solver) |

## Timeout Analysis

47 files timed out (hit the 180s or 300s limit). This is **not indicative of bugs**. The primary cause is CPU contention from running 5-6 batch processes in parallel on the same machine.

**Evidence:** Several files that timed out in one run passed in the other:

| File | Run 1 | Run 2 |
|------|-------|-------|
| mpb_data_analysis.py | TIMEOUT | PASS (123.9s) |
| test_mode_coeffs.py | TIMEOUT | PASS (183.5s) |
| test_n2f_periodic.py | TIMEOUT | PASS (276.3s) |
| test_prism.py | TIMEOUT | PASS (183.9s) |
| perturbation_theory.py | PASS (66.2s) | TIMEOUT |
| test_antenna_radiation.py | PASS (156.3s) | TIMEOUT |

Many timed-out files are known to be computationally intensive FDTD simulations (e.g., `binary_grating.py`, `mie_scattering.py`, `mode-decomposition.py`). With a 180s timeout and parallel batches competing for CPU, timeouts are expected for these workloads. Running them sequentially with a longer timeout (e.g., 600s) would resolve most of these.

## Recommendations

### Immediate (easy wins)

1. **Install `parameterized`:** `pip install parameterized` -- fixes 10 test failures instantly.
2. **Fix NumPy 2.x deprecations** in `antenna-radiation.py` and `solve-cw.py` -- two one-line changes.
3. **Install `h5utils`:** `sudo apt install h5utils` -- fixes 2 example failures.

### Short-term

4. **Fix API bugs** in `cavity_arrayslice.py`, `mpb_line_defect.py`, `waveguide_crossing.py`, and `binary_grating_levelset.py`. These are outdated example code that no longer matches the installed meep API. Submit patches upstream.
5. **Re-run timed-out files sequentially** with a 600s timeout on an idle machine to separate genuine hangs from CPU contention.

### Long-term

6. **Add `mymaterial.csv`** data file or a generation script for `eps_fit_lorentzian.py`.
7. **Document CLI-argument scripts** -- add a note or wrapper so batch runners can invoke them correctly.
8. **Consider adding `parameterized` to conda-forge pymeep dependencies** since 10 official tests require it.
